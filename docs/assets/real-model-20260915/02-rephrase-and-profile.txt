    - heading "是什么" [level=4]
    - paragraph: 把 Result 想成一个快递包裹：外包装上贴了一个标签 kind，要么是 "ok"，要么是 "error"。包裹里面装的东西取决于标签——"ok" 包裹里是 value，"error" 包裹里是 message。代码里检查 if (r.kind === "ok")，就像先看标签再拆包；只有确认标签是 "ok"，TypeScript 才让你伸手拿 value。
    - heading "为什么" [level=4]
    - paragraph: "TypeScript 不会猜测包裹里有什么。用 kind 这个字面量字段做标签后，一次 === 比较就等于告诉编译器“我已经看过标签了”，编译器才敢把 r 从联合类型缩成具体的 { kind: \"ok\"; value: number }，从而允许访问 value。"
    - heading "常见坑" [level=4]
    - paragraph: "别在没看标签前就拆包。下面这样会报错： ```ts type Result = | { kind: \"ok\"; value: number } | { kind: \"error\"; message: string }; function bad(r: Result) { return r.value; // 报错：Property 'value' does not exist } ``` 正确做法是在对应分支内访问： ```ts function good(r: Result) { if (r.kind === \"ok\") return r.value; return r.message; } ```"
